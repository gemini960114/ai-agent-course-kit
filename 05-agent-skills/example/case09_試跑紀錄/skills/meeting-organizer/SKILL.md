# Meeting Organizer

用於整理混在一起的政府或企業會議文件，自動判斷會議歸屬與文件類型並建立可讀的分類結構。

## 使用時機
- 使用者提到會議文件混亂、需要盤點、分類、整理會議資料
- 檔案夾內有多場會議的議程、簡報、會議紀錄、逐字紀錄等混放
- 需要產生盤點表、分類架構、README 與索引

## 工作流程

### 1. 盤點
- 讀取指定資料夾內每個檔案的內容，每個檔案先讀前 2000 字，必要時再往後讀
- 不要只看檔名，需以內容判斷所屬會議與文件類型
- 判斷標準：會議名稱、會議日期、召集單位、文件標題等
- 提出分類方案，包含：
  - 會議名稱與日期
  - 文件類型：議程、簡報、議程附件、會議紀錄、逐字紀錄等
  - 待確認清單：檔名與內容不一致、缺少文件、無法判斷歸屬者
- 提出方案後等待使用者確認，不要自行執行整理

### 2. 整理
- 使用者確認後，將檔案「複製」到指定輸出資料夾，不修改原始檔案
- 檔名改為可讀格式：`{會議名稱}_{文件類型}.{副檔名}`，例如 `107年度第1次會議_議程.docx`
- 目錄結構建議（`{輸出資料夾}` 以使用者指定的位置為準）：
  ```
  {輸出資料夾}/
  ├─ {會議名稱}_{日期}/
  │  ├─ 01_議程/
  │  ├─ 02_簡報/
  │  ├─ 03_議程附件/
  │  ├─ 04_會議紀錄/
  │  └─ 05_逐字紀錄/
  └─ _待確認/
  ```
- 無法判斷屬於哪場會議的檔案放入 `_待確認/`，不要硬分
- 只建立有檔案的資料夾；缺少的文件類型不要建空資料夾，改在 README.md 與 INDEX.md 註明缺漏

### 3. 說明
- 在輸出資料夾產生 `README.md`：
  - 分類邏輯
  - 檔案統計：總數、各會議數、文件類型數
  - 異常紀錄：命名不一致、缺漏、待確認
- 產生 `INDEX.md`：
  - 依年度、場次、文件類型建立索引
  - 每個項目列出新檔名連結與原始檔名對照
- 確認複製後的檔案數與原始檔案數一致

### 4. 核對
- 若使用者提供答案表或清冊，進行核對
- 以 INDEX.md 記載的原始檔名對照答案表，列出分類正確、分錯與遺漏
- 計算正確率
- 確認 INDEX.md 的連結都指向實際存在的檔案
- 無答案表時略過此步

## 重要原則
- 先讀內容再判斷，不要只看檔名
- 先盤點提出方案，等確認後再整理
- 複製不移動，原始檔案保持不變
- 遇到不確定時列入待確認，不要猜測
- 會議或文件類型寫法不同但意思相同視為正確

## 輸出格式
- 盤點結果以表格呈現：檔名、會議名稱、會議日期、文件類型、備註
- 最終交付：分類後的檔案結構、README.md、INDEX.md、核對報告 check.md（有核對時才產生），全部放在輸出資料夾內，不要寫到輸出資料夾以外的位置
